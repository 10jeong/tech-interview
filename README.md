# tech-interview
## 객체지향 (OOP)
<details markdown="1">
  <summary>인터페이스(Interface)와 추상 클래스(Abstract Class)의 차이점은 무엇인가요?</summary>
  <div>
    <ul>
      <li>인터페이스는 동작할 기능을 담은 명세서이고, 
추상 클래스는 공통되는 코드를 담은 클래스입니다.

인터페이스의 경우 확장에는 열려있고 변경에는 닫혀있다는 OCP 원칙에 따라 변경이 잦은 로직에 적합하고, 추상 클래스는 상속의 이점을 사용하여 공통적인 코드가 중복으로 작성되는 경우를 방지하는 데에 적합합니다.

+(경험)</li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>SOLID 원칙이란 무엇인가요?</summary>
  <div>
    <ul>
      <li>SOLID는 객체지향 설계의 5가지 원칙으로 유지보수성과 확장성을 높이기 위한 설계 원칙입니다. 
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>Class와 Object에 대해 설명해주세요.</summary>
  <div>
    <ul>
      <li>java의 Object는 모든 클래스의 부모 클래스입니다. 컴파일러가 자동으로 extends Object를 추가합니다.
클래스는 필드와 메서드로 구성되어 있습니다.
클래스는 객체를 생성하기 위한 설계도라는 설명도 있지만 반드시 그렇지는 않습니다.
Collection와 같이 클래스멤버 메소드로만 이루어진 경우가 있습니다.
객체(Object)는 속성과 동작으로 이루어진 것들을 포함하는 개념입니다.
java한정 클래스가 인스턴스된 것을 객체라고 할 수 있습니다.
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>Encapsulation(캡슐화)이란 무엇인가요?</summary>
  <div>
    <ul>
      <li>캡슐화는 관련된 기능과 데이터를 클래스라는 캡슐에 모으고 외부에서 내부 구현을 직접 알 수 없도록 은닉하는 것입니다. java에서는 필드에 private을 붙여 외부에서 접근할 수 없도록 하고, 생성자나 getter, setter를 이용해 접근창구를 하나로 통일하도록 설계합니다.
캡슐화를 통해서 응집도는 높히고 결합도는 낮춰, 내부 구현이 바뀌어도 외부 코드로 전파되는 영향을 최소화 합니다. 
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>다형성(Polymorphism)을 프로젝트에서 어떻게 활용했는지 예를 들어 설명해주세요.</summary>
  <div>
    <ul>
      <li>
프로젝트에서 상태 변경 검증 메서드를 추상화하여, 실제 상태 객체에 따라 서로 다른 검증 로직이 수행되도록 구성한 경험이 있습니다.
특히 동일한 메서드를 호출하더라도 각 상태 객체에서 오버라이딩된 메서드가 실행되도록 구현하면서, 런타임 시점에 실제 객체의 메서드가 선택되는 동적 바인딩 기반의 다형성 구조를 직접 경험할 수 있었습니다.
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>상속의 개념을 설명하고, 상속의 장단점을 이야기해 주세요.</summary>
  <div>
    <ul>
      <li>
        기존 클래스의 필드와 메서드를 새로운 클래스가 물려받아 기능을 확장하고 재사용할 수 있게 하는 객체지향 프로그래밍의 핵심 메커니즘입니다. 장점으로는 공통 로직의 중복을 제거하여 코드를 간결하게 유지할 수 있으며, 상위 타입으로 묶는 업캐스팅을 통해 다형성을 효과적으로 구현할 수 있습니다. 
        부모와 자식 클래스가 강한 결합으로 묶입니다. 부모 클래스의 작은 변경이 모든 자식 클래스에 치명적인 영향을 미칠 수 있으며, 자바는 단일 상속만 지원하므로 아키텍처 확장성에 제한이 생깁니다. 
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>상속 대신 조합을 사용하는 것이 적합한 경우는 언제인가요?</summary>
  <div>
    <ul>
      <li>
        클래스 간의 관계가 구체적인 포함 관계인 has-A 관계일 때 적합합니다.
        런타임에 동적으로 동작을 변경해야 할 때 필수적입니다. 상속은 컴파일 시점에 관계가 고정되지만, 조합은 실행 중에 주입된 객체를 교체하여 유연하게 대응할 수 있습니다.
        부모 클래스의 특정 구현 로직만 안전하게 재사용하고 싶을 때 사용합니다. 상속은 불필요한 public 메서드까지 자식에게 강제로 노출시켜 캡슐화를 깨뜨리지만 조합은 필요한 기능만 내부에서 호출하므로 안전한 것 같습니다.
      </li>
    </ul>
  </div>
</details> 




## 데이터베이스 (Database)
<details markdown="1">
  <summary>정규화와 역정규화의 차이를 설명해주세요.</summary>
  <div>
    <ul>
      <li>
        정규화는 데이터 중복을 제거하여 무결성을 높이는 설계 방식이고, 
        역정규화는 조회 성능 향상을 위해 중복을 허용하는 설계 방식입니다. 
        정규화는 데이터 정합성에 유리하지만 JOIN이 증가할 수 있고, 
        역정규화는 조회 성능은 좋아지지만 데이터 동기화 비용이 발생하는 트레이드오프가 있습니다.
      </li>
    </ul>
  </div>
</details> 

<details markdown="1">
  <summary>RDB와 NoSQL의 차이점을 설명해주세요.</summary>
  <div>
    <ul>
      <li>
rdb는 관계형 데이터 베이스로 고정된 스키마, 테이블 구조 형식을 띄고 있고 sql이라는 구조화된 질의를 사용합니다.
주된 장점으로는 트랜잭션의 원자성과 일관성에 따른 데이터 무결성을 보장합니다.<br>
nosql은 not only sql로 key-value, document 같이 유연한 스키마를 가지고, sql 대신 전용 쿼리, api 등으로 질의 합니다.
rdb보다 높은 쓰기 성능을 위해 사용하기도 하고, 특히 현대 웹개발에서는 고정된 테이블 구조에 맞추기 어려운 비정형 데이터를 저장하는 목적으로 사용 합니다.<br>
RDB는 고정된 스키마를 가져 스키마 변경시 큰 비용이 발생하고, nosql은 스키마가 유연하지만 데이터 정합성 관리가 어렵기 때문에 트레이드오프를 고려해서 서비스의 요구사항에 따라 개발자가 선택해야 합니다.
      </li>
    </ul>
  </div>
</details>
